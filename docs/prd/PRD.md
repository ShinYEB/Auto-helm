# 개인용 한국 주식 분석·자동매매 시스템 PRD

> 상태: 설계 초안 · 작성일: 2026-10-25 · 프로젝트명: Auto-helm
>
> 이 문서는 **무엇을 만들고 어떤 결과로 검증할지** 정의한다. API 필드, 저장 키, 장 단계별 처리 규칙은 하단의 설계 문서에서 관리한다.

## 1. 배경과 문제

사용자는 한국 주식을 거래하면서 매수·매도 근거를 충분히 기록하지 못했고, 수익이 자신의 판단에서 나온 것인지 시장 상승의 영향인지 구분하기 어려웠다. 시세, 뉴스, 공시는 다른 경로와 속도로 도착하므로 장중에 수작업으로 모아 일관되게 판단하고 사후에 재현하기도 어렵다.

사용하지 않는 Mac을 서버로 활용해 데이터를 모으고, AI와 가벼운 가격 모델을 시험하며, 판단·주문·결과를 연결해 검증한다. 시스템은 개인용이며 한국투자증권 계좌로 KRX와 NXT를 다룬다.

## 2. 목표와 성공 판단

| 목표 | 확인 방법 |
| --- | --- |
| 주식투자를 통한 수익 | 거래비용을 뺀 순수익, 최대 손실, 기준 전략 대비 성과를 기간별로 측정한다. 모의투자 성과를 실전 수익의 보장으로 해석하지 않는다. |
| 최신 기술 학습 | 실시간 수집, 시계열 예측, Jev 사건 분석, 비동기 처리, 클라우드 게시, 안드로이드 조회를 구현하고 각 실험의 결과를 남긴다. |
| 아키텍처 역량 향상 | 주요 설계 선택과 대안, 모델·API·AWS 비용, 장애 감지·복구·계좌 대조 결과를 기록한다. |

실전 거래 승격에 필요한 **평가 기간·최소 표본·허용 손실·주문 한도·지연 목표**는 구현 초기 측정 결과를 보고 수치로 확정한다. 수치가 확정되고 dev에서 검증되기 전에는 prd 자동주문을 켜지 않는다.

### 제품 성공의 최소 조건

- 모든 확정된 매매 판단에서 사용한 시세·예측·사건 신호·계좌 상태와 각 버전을 다시 찾을 수 있다.
- 누락되거나 오래된 필수 데이터가 있을 때 새 매수 주문을 만들지 않는다.
- 통신 오류와 재시작 시험에서 동일한 의도에 대한 중복 주문이 발생하지 않는다.
- dev 계좌·인증정보·기록과 prd 계좌·인증정보·기록이 섞이지 않는다.
- AWS 모니터링 경로의 지연·장애가 Mac의 시세 수집과 로컬 판단을 멈추지 않는다.

## 3. 사용자와 핵심 사용 시나리오

**사용자:** 한국 주식을 거래하며 개발 과정을 기록하는 개인 투자자 1명. Mac에서 시스템을 운영하고, 안드로이드 앱으로 상태를 조회한다.

1. 장중에 관심 종목의 최신 시세, 가격 예측, 관련 뉴스·공시 신호, 매매 판단과 이유를 확인한다.
2. 매매가 제안되거나 실행되면 어떤 입력과 규칙이 쓰였는지, 실제 주문·체결 결과가 무엇인지 나중에 조회한다.
3. dev 모의계좌에서 전략과 주문 복구를 시험한 뒤 검증된 버전을 prd 실전계좌에 배포한다.
4. Mac이나 외부 API에 문제가 생기면 최신 상태의 시각과 주문 중지 여부를 확인하고 안전하게 복구한다.

## 4. 범위와 단계

| 단계 | 제공 범위 | 주문 상태 |
| --- | --- | --- |
| M1 · 수집과 기록 | 관심 종목, KRX·NXT 시세, 1분 봉, 누락 감지·복구, 로컬 기록·조회 | 주문 없음 |
| M2 · 분석과 판단 | 뉴스·공시 수집, Jev 사건 신호, 가격 기준선·모델 비교, 판단과 근거 기록 | 주문 없음 |
| M3 · 모의투자 | dev의 한투 모의계좌 주문·체결·취소·대조, 장애 복구, 성과 평가 | dev만 허용 |
| M4 · 모니터링과 실전 | 안드로이드 조회, dev/prd 모니터링 분리, 승격 조건을 통과한 prd 거래 | 조건 충족 후 prd 허용 |

안드로이드 모니터링은 dev에서 먼저 검증할 수 있다. M4의 실전 주문은 별도 승격 조건을 통과해야 활성화한다.

### 현재 범위에서 제외

- 다중 사용자 서비스, 타인의 계좌 관리, 외부 사용자 대상 투자 추천
- 안드로이드 앱에서의 주문·취소 또는 전략 변경
- AI 응답만으로 주문 실행
- 모든 원시 체결 틱·뉴스 전문을 무기한 보관
- Mac 서버를 클라우드로 이전하거나 장중에 모델을 재학습하는 기능

### 판단 정책의 초기 원칙

- 1시간 뒤와 현재 장 단계의 종료 가격 예측을 주요 방향 근거로 사용하고, 다음 1분 예측은 진입 시점의 위험을 확인하는 데 쓴다.
- 뉴스·공시 신호는 실제 분석이 완료된 시점부터만 판단에 사용할 수 있다.
- 거래비용, 데이터 최신성, 보유량, 현금, 미체결 주문, 시장·종목별 주문 가능 여부, 포지션 한도를 코드에서 검사한다.
- 가격 신호가 충돌하거나 필수 예측 목표가 유효하지 않으면 기본 판단은 대기다. 보유 포지션의 위험 청산은 별도 규칙으로 검토한다.
- Jev를 매매 후보 검토에 추가하더라도 최종 주문 제약 검사는 코드가 수행한다. 판단 임계값과 신호 유효기간은 시간순 검증을 거쳐 정한다.

## 6. 데이터와 시스템 경계

```text
KRX·NXT 시세 ─→ 봉·예측 ─┐
뉴스·공시 ────→ Jev 신호 ─┼→ 최신 상태 → 판단 기록 → 주문 실행기 → KIS 계좌
계좌·호가 ───────────────┘         │
                                  ├→ 로컬 파일 원본 → 학습·검증용 Parquet
                                  ├→ 환경별 DynamoDB 검색 인덱스
                                  └→ AWS 모니터링 사본 → API Gateway·Lambda → Android
```

| 저장 위치 | 제품에서 맡는 역할 |
| --- | --- |
| Mac 메모리 | 장중 종목별 최신 봉·호가·예측·사건 신호·계좌 상태와 판단 입력 |
| 환경별 날짜별 JSONL | 확정된 데이터와 판단·주문의 원본 기록, 재시작과 감사의 기준 |
| 환경별 Parquet | 장 마감 후 정리한 학습·검증·백테스트 데이터 |
| DynamoDB Local(dev) / AWS DynamoDB(prd) | 종목별 사건·판단 검색 인덱스. 장중 판단의 필수 경로는 아님 |
| AWS dev/prd 모니터링 테이블 | 최신 작은 스냅샷과 주요 이벤트의 원격 조회 사본 |

시세 수신, 봉 계산·추론, 뉴스·공시 조회, Jev 호출, 판단, 기록·게시 작업은 비동기 큐로 연결한다. 로컬 기록을 확정한 뒤 DB 인덱싱과 AWS 게시를 재시도 가능한 별도 작업으로 넘긴다. 원격 저장 지연이 장중 판단을 기다리게 하지 않는다.

## 7. 비기능 요구사항

| 영역 | 요구사항 | 검증 방법 |
| --- | --- | --- |
| 데이터 정확성 | 제공처 시각, 수신 시각, 분석 완료 시각을 구분하고 미래 정보를 과거 판단에 넣지 않는다. | 저장된 입력 ID와 시각으로 한 판단을 재현한다. |
| 지연 | 1분 봉 완성에서 판단 확정까지의 시간, Jev 대기 시간, 뉴스·공시 발견 지연을 측정한다. | 실제 장중 분포를 기록하고 승격 전 허용치를 고정한다. |
| 장애 대응 | 시세 누락, 큐 초과, 파일 쓰기 실패, 오래된 계좌·호가에서 신규 진입을 보류한다. | 각 장애를 주입해 보류 기록과 복구 후 재개를 확인한다. |
| 주문 안전성 | 주문 의도와 증권사 접수·체결 상태를 대조하고 중복을 방지한다. prd에는 즉시 작동하는 주문 중지 수단을 둔다. | 응답 시간 초과·재시작·부분 체결 시나리오를 dev에서 반복한다. |
| 환경 격리 | dev/prd의 계좌, 자격 증명, 저장소, 모니터링 테이블, 배포 버전을 분리한다. | 교차 접근을 시도해 거부 여부를 확인한다. |
| 비용 | AI 호출은 새 항목과 필요한 판단에 제한하고, AWS에는 작은 사본만 보낸다. | 종목·일자·환경별 모델 호출량과 AWS 사용량을 기록하고 예산 경보를 둔다. |
| 보안 | KIS·AWS 키를 코드, 원본 데이터, 로그, 모바일 앱에 노출하지 않는다. | 배포 설정과 로그·앱 산출물의 비밀정보 검사를 수행한다. |
| 관측 가능성 | 마지막 봉·계좌 확인 시각, 큐 지연, AI 실패, 주문 중지 여부를 볼 수 있다. | 상태 화면과 장애 기록에서 지연·중단 원인을 식별한다. |

Mac은 dev/prd가 같은 물리 장비를 공유하는 단일 장애 지점이다. 환경 분리만으로 하드웨어 장애를 해결할 수 없으므로 prd 원본 파일·모델·설정을 별도 위치에 백업한다. 장애 후에는 로컬 기록을 복원하고 KIS 주문·체결·잔고를 대조한 다음 신규 주문을 재개한다.

## 8. 실전 승격 조건

1. **과거 검증:** 시간순으로 분리한 데이터에서 가격 기준선, 모델, 매매 규칙을 비교한다. 거래비용과 체결 가능한 가격을 반영한다.
2. **dev 거래 검증:** 동일한 릴리스로 한투 모의계좌에서 주문, 거부, 부분 체결, 정정·취소, 재시작, 통신 오류를 시험한다.
3. **운영 검증:** 시세 누락, AWS 장애, AI 지연, 파일·DB 장애에서 주문 중지와 복구가 의도대로 동작한다.
4. **버전 고정:** 코드 이미지, 모델, 규칙·프롬프트, 설정 스키마를 릴리스 ID로 묶고 dev에서 검증한 그대로 prd에 배포한다. 계좌·데이터·비밀정보는 승격하지 않는다.
5. **prd 첫 가동:** 읽기 전용으로 인증·시세·잔고·미체결·시장 상태를 확인한 뒤 제한된 주문 한도로 시작한다. 첫 주문과 체결을 KIS 내역과 대조한다.

각 게이트의 통과 수치와 관찰 기간은 M1~M3 실측 후 문서에 고정한다. 미정 상태는 통과로 간주하지 않는다.

## 9. 결정이 필요한 항목과 리스크

| 항목 | 현재 상태 / 다음 확인 |
| --- | --- |
| 프로젝트명 | GitHub 저장소 이름은 Auto-helm이다. 공개 표시 이름의 표기는 추후 확정한다. |
| 한투 모의·실전 기능 범위 | KRX·NXT·SOR 채널, 분봉 복구, 주문 유형과 모의 체결 통지 지원을 실제 계좌에서 확인한다. |
| 모델의 실효성 | 단순 기준선보다 예측 오차와 비용 반영 매매 결과가 나은지 시간순 평가로 확인한다. 개선이 없으면 기준선을 유지한다. |
| 뉴스·공시 지연 | 초기 조회 주기를 운영 지표와 제공처 한도에 맞춰 조정한다. 빠른 공시 대응이 필요한 전략이면 지연을 별도로 평가한다. |
| 예산·위험 한도 | 월별 모델·AWS 예산, 종목별·일별 주문 한도, 허용 손실과 운영 경보 수치를 확정한다. |
| 시세 재표시 권한 | 한투 시세를 안드로이드 앱에 보여줄 수 있는 범위를 사용 조건에서 확인한다. |
| Mac 장애 | 정전·네트워크·디스크 장애는 dev/prd에 함께 영향을 준다. 백업·복구 소요 시간과 수동 주문 중지 절차를 시험한다. |
