# 뉴스·공시 데이터 수집 경로 확인

> 확인일: 2026-10-26
>
> 상태: 공시 경로 확인, 일반 뉴스 분석용 제공처 미확정

## 결론

1. **공시는 OpenDART API로 수집할 수 있다.** 기업 고유번호를 매핑하고 공시 목록을 장중 주기적으로 조회한 뒤, 새 접수번호의 원본 서류를 가져오는 경로가 공식적으로 제공된다.
2. **네이버 뉴스 검색 API를 AI 분석용 수집원으로 채택하지 않는다.** NAVER API HUB의 현행 약관은 검색 결과를 AI에 입력하거나 학습·개선·평가에 활용하는 것을 금지한다. 기술적으로 검색이 가능하다는 사실은 이 프로젝트의 뉴스 분석 용도를 허용한다는 뜻이 아니다.
3. **일반 뉴스는 이용권한과 지연을 확인할 때까지 판단 입력으로 연결하지 않는다.** 뉴스토어의 일반 분석용 뉴스데이터 상품도 **AI 활용을 금지**한다. 별도 인공지능용 뉴스데이터 상품은 있으나 개인 프로젝트의 구매 자격·가격·실시간 API 범위·외부 AI 서비스 입력 허용 여부는 계약 확인이 필요하다.

## 공시 수집의 첫 구현 경로

```text
종목코드 목록
  → OpenDART 기업 고유번호 매핑
  → 장중 15분마다 해당 날짜 공시 목록 조회
  → 접수번호로 중복 제거·정정 공시 연결
  → 새 접수번호만 원본 서류 다운로드
  → 원본·발견 시각 기록
  → 별도 비동기 분석 대기열
```

- 공시 목록은 `last_reprt_at=N`으로 조회해 정정 보고서도 포함한다. 관심 종목이 적다면 당일 전체 목록을 페이지 끝까지 읽고 종목코드로 필터링하는 방식과 기업별 조회의 실제 요청 수를 비교한다.
- 시작·재시작 시 직전 조회 기간을 겹쳐 다시 읽는다. 같은 접수번호는 한 번만 저장·분석하고, 정정 접수번호는 새 사건으로 남긴다.
- 응답의 `rcept_dt`는 **날짜만 제공**한다. 공시 발생의 분·초를 이 API 필드만으로 단정할 수 없으므로 `firstSeenAt`을 반드시 기록한다. 더 정확한 접수 시각을 얻는 경로가 필요한지는 실제 서류·추가 제공처에서 확인한다.
- OpenDART는 요청 제한 초과 코드 `020`을 설명하며 일반적으로 20,000건 이상의 요청에서 발생할 수 있으나 계정별 제한이 다를 수 있다. 15분 주기 자체보다 **페이지·기업별 호출 수**와 일일 누계를 관리한다. [오류 코드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001)
- API 키, 실제 응답 필드, 원본 ZIP 파싱, 접수번호와 정정 공시 관계는 구현 전에 표본으로 검증한다.

## 뉴스 수집원을 선택할 때 확인할 조건

일반 뉴스의 목표는 단순한 링크 표시가 아니라 **새 기사 발견 → 종목 관련성 판단 → AI 사건 분석 → 판단 당시 근거 보존**이다. 제공처에 다음 사용이 명시적으로 허용되는지 확인한다.

| 확인 항목 | 필요한 답 |
| --- | --- |
| 접근 | 개인 사용자도 API 계약·발급이 가능한가? 기사 목록과 본문/요약을 각각 받을 수 있는가? |
| 지연·범위 | 국내 경제지·관심 종목을 얼마나 빨리, 얼마나 빠짐없이 제공하는가? 1분 조회가 의미 있는가? |
| 이용권 | 기사 텍스트를 로컬에 기록하고 외부 AI 서비스에 입력해 사건 분석에 사용할 수 있는가? 보존·삭제 조건은 무엇인가? |
| 비용·한도 | 최소 계약 금액, 건당/월별 비용, 호출 제한, 시험 환경이 있는가? |
| 중복·수정 | 기사 고유 ID와 발행·수정 시각이 있는가? 정정·삭제 기사를 어떻게 알리는가? |

제공처를 확정하기 전에는 HLD의 **뉴스 1분 조회를 구현 확정값으로 취급하지 않는다.** 계약에서 허용된 메타데이터·본문만 기록하고, 그 범위에서 분석기를 설계한다. 원문 URL이 있다고 해서 사이트 본문을 자동 수집할 권리가 생기는 것은 아니다.

## 바로 이어질 작업

1. OpenDART 키를 발급해 관심 종목 한두 개로 고유번호·목록·원본 서류를 시험한다. 실제 API 호출 전에는 키가 필요하다.
2. 공시 수집 LLD와 구현을 진행한다. 뉴스 경로와 별도 작업자로 두어 뉴스 제공처 선정이 공시 수집을 막지 않게 한다.
3. 뉴스토어의 **인공지능용 뉴스데이터**에 개인용 자동매매 연구, 실시간 API, 외부 LLM 추론 입력 조건의 계약 가능 여부와 견적을 확인한다. 대안 제공처도 동일한 조건으로 비교한다.
