# 개인용 한국 주식 분석 앱 설계 기록

## 프로젝트 목표

1. **주식투자를 통한 수익**: KRX·NXT 데이터, 가격 예측, 뉴스·공시 신호를 활용해 거래비용을 반영한 매매 전략을 만들고, 모의투자에서 검증한 뒤 실전 계좌에 적용한다. 성과는 순수익, 최대 손실, 거래비용, 기준 전략 대비 결과로 평가한다. 수익은 목표이며 예측이나 모의투자 성과가 실전 수익을 보장하지는 않는다.
2. **최신 기술 스터디**: 실시간 웹소켓 수집, 상태 유지형 시계열 모델, Jev 의사결정 모델, 비동기 처리, DynamoDB, API Gateway·Lambda, 안드로이드 모니터링, dev/prd 배포와 관측을 직접 구현하고 검증한다. 실험 결과와 설계 선택의 근거를 기록한다.
3. **주니어 개발자의 아키텍처 설계 역량 쌓기**: 요구사항을 데이터 흐름·서비스 경계·저장 구조·배포·장애 복구로 구체화한다. 주요 설계마다 선택 이유와 대안을 기록하고, AWS 호출·저장·모델 사용 비용을 측정해 최적화한다. 장애 감지, 주문 중지, 데이터 복구, 계좌 대조를 검증해 운영 안정성을 확보하고, 실제 운영 결과를 바탕으로 설계를 개선한다.

세 목표를 함께 추구하되, 새로운 기술은 먼저 dev에서 실험하고 매매 성과와 장애 복구를 확인한 릴리스만 prd에 승격한다.

로컬 Mac에서 KRX·NXT 웹소켓 시세를 받아 종목별 상태를 갱신하고, 매분 다음 1분 가격·1시간 뒤 가격·당일 종료 가격을 예측한다. 당일 종료 가격은 KRX 공식 종가와 NXT 애프터마켓 종료 기준 가격을 구분한다. 뉴스와 공시는 별도 경로로 수집해 필요한 경우 Jev로 분류한다. 예측값을 매매 후보로 바꾸는 임계값은 검증으로 정한다.

데이터 출처, 환경별 로컬 파일·DynamoDB 저장 구조와 판정 시점의 결합 규칙은 [데이터 수집 저장 결합 판정 설계](DATA_PIPELINE.md)에 구체화했다.

두 시장의 시간대·체결 채널·가격 목표·주문 경로는 [KRX·NXT 통합 설계](MARKETS.md)를 따른다.

각 데이터의 원본 위치, 장중 읽기 순서, 인덱스·복구 기준은 [데이터 저장·사용 계약](DATA_CONTRACTS.md)에 모았다.

증권사는 한국투자증권으로 확정했으며 실시간 채널·분봉·계좌·주문 API 대응은 [KIS 연동 명세](KIS_INTEGRATION.md)를 따른다.

모의투자 주문이 가능한 `dev`와 실전 주문이 가능한 `prd`의 파드·계좌·비밀정보·파일·DB 경계 및 승격 절차는 [dev·prd 거래 환경](ENVIRONMENTS.md)에 정의한다.

안드로이드에서 두 환경의 상태를 조회하는 AWS 게시·API Gateway·Lambda 경로는 [원격 모니터링](MOBILE_MONITORING.md)에 정의한다.

## 앱 구성

초기 기능은 Mac에서 판단과 기록부터 구현한다. 거래 연결 단계에서는 동일한 코드 이미지를 별도 dev·prd 파드에 배포하고, 각 환경의 파일과 DB를 분리한다. dev 검색 인덱스는 DynamoDB Local, prd 검색 인덱스는 관리형 DynamoDB를 쓴다. 장 마감 후 시계열은 환경별 Parquet로 정리한다. 서버 안에서 시세 수신, 정기 조회, 모델 추론, 화면 API, 인덱스 기록을 별도 비동기 작업으로 실행한다. 장중 판정은 메모리의 최신 상태를 사용하며 DB 조회를 기다리지 않는다. 장중 재학습은 하지 않고, 학습 작업은 장 마감 후 별도 실행한다.

```text
KRX·NXT 웹소켓 → 시장별 시세 수신 → 1분 봉·지표 → 종목별 모델 상태 → 시세 예측 ─┐
                                                                           ├→ 매매 판단기 → 판단 기록 → 로컬 화면
뉴스 검색 API ─→ 1분 조회 ──→ 신규 기사 판별 ─→ Jev ─→ 뉴스 이벤트 신호 ──────┤
OpenDART ─────→ 15분 조회 ─→ 신규 공시 판별 ─→ Jev ─→ 공시 이벤트 신호 ──────┘
                             ↘ 날짜별 로컬 기록 → 장 마감 후 Parquet → 학습·검증
                                         ↘ 인덱스 큐 → 환경별 DynamoDB 이벤트·판정 검색
                                         ↘ 게시 큐 → AWS dev/prd 모니터링 테이블 → API Gateway·Lambda → Android
```

가격 예측과 텍스트 이벤트는 시간과 종목 코드, 거래 시장·장 단계를 기준으로 매매 판단기에 전달한다. 판단기는 1시간 뒤와 해당 장 단계의 종료 목표를 주된 방향 근거로 쓰고 다음 1분 예측으로 진입 시점의 위험을 확인한다. 보유 수량, 현금, 거래비용, 주문 가능 여부, 데이터 최신성, 포지션 한도도 검사해 매수·매도·대기 후보와 이유를 기록한다. 임계값은 과거 기간 검증 뒤 정한다. Jev 응답을 받기 위해 시세 수신이나 1분 봉 처리를 멈추지 않는다. Jev 요청이 실패하면 해당 이벤트를 재시도 대상으로 기록하고 시세 분석은 계속한다.

웹소켓 수신, 봉 계산·모델 추론, 뉴스·공시 조회, Jev 요청, 매매 판단, 파일·DB 기록은 서로 다른 비동기 작업과 큐로 분리한다. 웹소켓 수신 작업은 네트워크 메시지를 읽고 시세 큐에 전달하는 일만 한다. Jev 호출은 제한된 개수만 동시에 실행한다. 큐가 넘치거나 시세 연결이 끊기면 누락 구간을 표시하고 분봉 조회로 복구할 때까지 해당 종목의 매매 후보를 보류한다. 판정용 Jev 응답이 돌아왔을 때는 입력 봉·계좌·신호 버전이 현재와 같은지 다시 검사한다.

판단기는 새 1분 봉이나 관련 뉴스·공시 분석 결과가 도착할 때 코드에서 갱신한다. 데이터가 오래됐거나 판단에 필요한 값이 없으면 그 이유와 함께 대기를 반환한다. 유효한 1시간·해당 장 단계의 종료 목표 예측에서 거래비용을 뺀 결과가 모두 매수 기준을 넘고 1분 위험 신호가 낮으면 매수 후보, 보유 중 두 기간 모두 약세이면 매도 후보를 만든다. 서로 충돌하면 기본값은 대기다. 가격 후보가 생기거나 새 사건 신호가 들어온 경우에만 Jev에 사건과 가격 판단의 충돌 여부를 요청한다. 동일한 입력 ID 조합에는 재호출하지 않고 종목별 호출 간격도 제한한다.

매매 판단기와 주문 실행은 별도 모듈이다. 첫 단계에서는 판단 기록과 화면 표시를 구현한다. 다음 단계에서 dev의 한투 모의계좌에 실제 API 주문을 보내고, 검증된 릴리스만 prd의 한투 실전계좌에 배포한다. 두 환경의 주문·체결·계좌 기록은 섞지 않는다.

추후 비교 실험에서는 Jev에 정리된 시장 상태와 뉴스·공시 이벤트를 보내 매수·매도·대기 후보 자체를 분류하게 할 수 있다. 이 경우에도 수익률, 거래비용, 주문 가능 수량, 데이터 최신성은 코드에서 먼저 계산한다. Jev의 후보는 로컬 주문 제약 검사를 통과해야 유효한 판단으로 기록한다. 이 방식의 매매 성과는 기본 코드 판단기와 같은 기간에서 비교한 뒤 채택한다. Jev의 응답 확률은 미래 주가 상승 확률로 취급하지 않는다.

1분 봉, 뉴스·공시, Jev 결과와 매매 판단은 환경별 날짜별 로컬 추가 기록 파일에 남긴다. 완료된 시세 기록은 장 마감 후 Parquet로 묶어 학습과 검증에 사용한다. 이벤트와 판정의 작은 메타데이터는 환경별 DynamoDB 인덱스에, 모바일용 최신 스냅샷과 주요 이벤트는 환경별 AWS 모니터링 테이블에 비동기 게시한다. AWS 게시가 늦어져도 로컬 판정과 주문은 이를 기다리지 않는다. 종목별 LSTM 내부 상태는 메모리에 두고 재시작 시 저장된 최근 봉으로 다시 만든다. API 키는 데이터 파일과 로그에 평문으로 남기지 않는다.

## 시세와 시계열 모델

1. 증권사 웹소켓에서 체결가와 거래량을 수신한다.
2. 앱에서 1분 봉과 수익률, 거래량 변화, 변동성 등의 지표를 계산한다.
3. 종목별로 이전 내부 상태를 보관한다. 새 1분 데이터와 이전 상태를 작은 상태 유지형 LSTM에 넣어 다음 상태와 네 예측값을 얻을 수 있다.
4. 매분에는 추론과 상태 갱신만 수행한다. 모델 가중치는 이 단계에서 바꾸지 않는다.
5. 재시작이나 데이터 누락 시에는 저장한 상태를 복원하거나 최근 데이터를 순서대로 다시 입력한다. 거래가 끊기는 경계에서는 상태 초기화 정책을 정한다.

LSTM은 시험할 후보이다. 먼저 더 가벼운 기준선인 로지스틱 회귀와 점진적으로 갱신되는 지표를 구현해 같은 기간에서 비교한다. 종목마다 모델을 하나씩 학습하기보다는 관심 종목을 묶은 작은 공통 모델을 우선 검토하고, 실시간 내부 상태는 종목별로 분리한다.

예측 기준점 `C_t`는 방금 완성된 통합 1분 봉의 기준 가격이다. 학습 목표는 다음 1분, 60분 뒤, 당일 KRX 공식 종가, NXT 애프터마켓 종료 기준 가격의 `목표 가격 / C_t - 1` 수익률이다. 실제 화면에는 예측 수익률을 가격으로 환산해 보여준다. 한 개의 작은 상태 모델에 네 출력 헤드를 붙여 매분 한 번 추론하는 구성을 우선 시험하고, 목표별 단순 기준선과 비교한다. 각 예측에는 거래 시장·장 단계, 목표 시각, 모델 버전, 유효 여부를 함께 저장한다. 1분·60분 목표가 비거래 구간에 걸리거나 NXT 거래 가능 종목이 아니면 해당 출력을 무효 처리한다. KRX 종가와 NXT 종료 기준 가격을 같은 정답으로 합치지 않는다.

## 최초 학습과 평가

과거 시장별 1분 봉과 통합 봉을 시간순으로 정렬하고, 각 시점에 실제로 알 수 있었던 값만 입력으로 사용한다. 정답은 다음 1분, 1시간 뒤, KRX 공식 종가와 NXT 종료 기준 가격의 실현 수익률이다. 목표 시각에 거래가 없거나 신선한 기준 가격이 없으면 해당 출력의 손실 계산에서 제외한다. 각 종료 목표에는 남은 거래 시간과 현재 장 단계 정보를 입력으로 포함한다. 학습에서는 각 출력과 실제 정답을 비교해 가중치를 조정하되, 시간대별 변동성 차이 때문에 한 목표가 학습을 지배하지 않도록 출력별 손실 크기를 조정한다. 사전 학습된 모델을 추가 학습하는 경우가 파인튜닝이며, 빈 모델로 시작하면 최초 학습이다.

학습 기간보다 뒤의 기간에서 시간 순서대로 검증한다. 기준선, 거래비용, 지연과 실제 체결 가능한 가격을 포함해 결과를 비교한다. 정확도와 실거래 유용성을 별도로 평가한다. 모델 학습은 장 마감 후 또는 정해진 주기로 실행하고, 장중에는 저장된 가중치로 추론한다.

## 뉴스와 공시의 역할

시세 웹소켓은 가격 데이터 경로다. 뉴스와 공시는 제공처의 검색 API, 공시 API 또는 RSS에서 별도로 수집하고 중복을 제거한다. Jev에는 새로 들어온 관련 기사나 공시의 제목·요약·메타데이터와 판단 질문을 보낸다. Jev 출력은 텍스트 이벤트 신호로 저장하고, 미래 수익률 확률로 바로 해석하지 않는다.

최초 실행 시 관심 종목의 과거 공시를 한 번 가져와 저장하고, 이후에는 새 공시를 주기적으로 확인한다. 일반 뉴스는 종목별 검색을 주기적으로 실행한다. 조회 주기는 소스별 호출 한도와 허용 지연을 보고 정한다. 같은 기사나 공시를 매 조회마다 다시 분석하지 않고, 새 식별자만 Jev에 보낸다. 앱 시작이나 통신 복구 뒤에는 누락 구간을 다시 조회한다.

기본 공시 확인은 장 시작 전과 장 마감 후에 수행하고, 장중에는 15분 간격으로 새 공시를 확인한다. 관심 종목 수와 OpenDART 요청 한도를 모니터링하며 주기를 조정한다. 공시 조회 주기와 Jev 분석 횟수는 다르며, Jev는 새 공시가 발견됐을 때만 호출한다. 빠른 공시 직후 매매를 목표로 할 경우 15분 조회 지연을 별도로 평가한다.

저장 항목에는 원본 식별자, 종목 코드, 원문 링크, 제공처의 게시 또는 접수 시각, 앱 수신 시각, Jev 분석 결과를 포함한다. 공시 정정은 기존 공시와 관련을 맺되 별도 새 항목으로 처리한다.

## 전체 알고리즘

아래의 `매매 임계값`, `신호 유효기간`, `주문 한도`는 검증으로 정할 설정값이다. 예측 목표는 다음 1분, 1시간 뒤, KRX 공식 종가와 NXT 종료 기준 가격이다.

### 준비와 최초 학습

1. 관심 종목의 과거 1분 봉을 모으고, 결측·중복·거래 중단 구간을 표시한다.
2. 각 시점에서 그때까지 알 수 있었던 시장별 가격·거래량 지표를 입력으로 만들고, 다음 1분·1시간 뒤·KRX 공식 종가·NXT 종료 기준 가격의 수익률을 각각 정답으로 만든다. 거래가 없거나 누락된 목표는 해당 출력의 학습에서 제외한다.
3. 날짜 순서대로 학습·검증·최종 평가 기간을 나눈다. 지표 정규화는 학습 기간 값으로만 맞춘다.
4. 단순 기준선과 작은 LSTM을 같은 기간에 비교한다. 예측 오차와 거래비용을 포함한 모의 매매 결과를 함께 본다.
5. 채택한 모델 가중치, 정규화 값, 특징 목록, 네 목표 정의와 시장 단계, 모델 버전을 저장한다. 매매 임계값도 학습 기간 밖의 검증 결과로 정한다.

### 장중 수집과 추론

```text
앱 시작:
  저장된 모델·설정·관심 종목을 로드한다.
  오늘의 최근 1분 봉으로 종목별 상태를 복원하거나 다시 만든다.
  뉴스·공시 누락 구간을 조회한다.

시세 틱 수신 시:
  해당 종목의 현재 1분 봉을 갱신한다.

1분 봉 완성 시:
  현재 시점까지의 지표를 계산한다.
  종목별 LSTM 상태를 한 단계 갱신하고 다음 1분·1시간 뒤·KRX 공식 종가·NXT 종료 기준 가격의 예상 수익률을 얻는다.
  예측값·목표 시각·유효 여부·입력 시각·모델 버전을 저장한다.
  매매 판단을 요청한다.

뉴스 조회 주기(초안: 1분):
  관심 종목의 최신 기사 목록을 가져온다.
  원문 URL 등으로 중복을 제거하고 처음 발견한 시각을 기록한다.
  관련 가능성이 있는 새 기사만 Jev로 사건 유형·종목 관련성 등을 분석한다.
  분석 결과를 저장하고 해당 종목의 매매 판단을 다시 요청한다.

공시 조회 주기(장중: 15분):
  새 공시 목록을 가져와 접수번호로 중복을 제거한다.
  정정 공시는 관련 이전 공시와 연결된 새 항목으로 저장한다.
  새 관련 공시를 Jev로 분석하고 해당 종목의 매매 판단을 다시 요청한다.
```

### 매매 판단

```text
매매 판단 요청 시:
  최신 시세·예측·보유량·현금·기존 미체결 주문을 읽는다.
  현재 시점에 앱이 이미 발견한 뉴스·공시 신호만 읽는다.
  코드에서 1시간·현재 장 단계의 종료 목표에 대한 예상 순수익과 1분 위험 신호를 계산한다.
  데이터가 오래됐거나 예측 목표가 무효이면 신규 진입은 대기를 기록한다.
  두 기간이 모두 강세이고 비용·1분 위험 검사를 통과하면 매수 후보를 만든다.
  보유 중 두 기간이 모두 약세이거나 별도 위험 청산 조건이면 매도 후보를 만든다.
  기간별 판단이 충돌하면 대기를 기록한다.
  가격 후보 또는 새 사건 신호가 있을 때만 Jev에 사건과 가격 판단의 충돌 여부를 요청한다.
  로컬 코드에서 자금·보유량·한도·중복 주문·신호 유효기간을 최종 검사한다.
  후보, 최종 판단, 네 예측값이 담긴 기록 ID, 선택한 시장·장 단계, 이유, 입력 시각, Jev 및 규칙 버전을 저장한다.
  주문 기능이 활성화된 환경에서는 별도 주문 실행기가 계좌·주문 상태를 재확인한 뒤 dev 모의계좌 또는 prd 실전계좌로 보낸다.
```

Jev가 반환한 사건 분류 확률을 실제 수익 확률로 해석하지 않는다. Jev가 실패하거나 응답이 늦으면 기존 시세 수신은 계속하고, 신규 진입 후보는 대기 또는 미확정으로 기록한다. 장 마감 후에는 그날의 새 봉을 학습 후보에 넣고, 날짜 순서의 평가를 통과한 모델만 다음 장에 적용한다.
