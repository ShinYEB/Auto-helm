# KRX·NXT 통합 시세와 예측·주문 설계

이 문서는 한국투자증권 Open API로 한국거래소(KRX)와 넥스트레이드(NXT)를 함께 보는 개인용 Mac 앱의 시장 경계를 정의한다. 시각은 한국 표준시다. 채널·주문 코드 대응은 [KIS 연동 명세](KIS_INTEGRATION.md)에 둔다. 실제 계좌 권한은 첫 연결 시험에서 확인한다.

## 1. 거래 시간과 장 단계

| 시장·단계 | 체결 시간 | 앱에서의 처리 |
| --- | --- | --- |
| NXT 프리마켓 | 08:00~08:50 | NXT 전용 시세·호가, 별도 장 단계 |
| KRX 정규장 | 09:00~15:30 | 마감 15:20~15:30은 동시호가로 구분 |
| NXT 메인마켓 | 09:00:30~15:20 | KRX와 동시에 거래되는 구간 |
| NXT 애프터마켓 | 15:40~20:00 | NXT 전용 시세·호가, 별도 장 단계 |
| NXT 종가매매시장 | 15:30~16:00 체결 | KRX 공식 종가로 체결하는 별도 주문 방식 |

NXT 애프터마켓은 15:30부터 호가를 접수하나 정규시장의 실제 체결은 15:40부터다. KRX 시가·종가 동시호가에 호가를 모으기 위해 NXT가 중간에 멈추는 구간이 있다. NXT 거래 가능 종목은 정기·수시로 바뀌므로 일별 대상 목록을 저장하고, 주문 직전에도 해당 종목의 NXT 거래 가능 여부를 확인한다. 표의 시각은 기본 일정이며 특별 휴장, 장중 중단, 거래시간 연장은 당일 시장 상태를 우선한다. [NXT 거래제도](https://www.nextrade.co.kr/menu/transactionSys.do), [NXT 대상 종목 변경 공지](https://nextrade.co.kr/menu/notice/menuList.do?menuCode=notice), [KRX 거래 시간](https://global.krx.co.kr/contents/GLB/06/0602010201/GLB0602010201T1.jsp).

## 2. 시세 수집과 정규화

증권사 어댑터는 KRX 체결·호가와 NXT 체결·호가를 각각 구독한다. 한국투자증권 예시에는 KRX 체결 `H0STCNT0`, NXT 체결 `H0NXCNT0`, 통합 체결 `H0UNCNT0`, NXT 호가 `H0NXASP0`, 통합 호가 `H0UNASP0`가 있다. 통합 체결을 모델의 기준 입력으로 선택한 경우 개별 KRX·NXT 체결을 다시 합산하지 않는다. 개별 채널은 시장별 호가와 장애 확인에 사용한다. 실제 통합 채널의 시장 코드·중복 관계는 연동 시험에서 확인한다. [KIS 웹소켓 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_user/domestic_stock/domestic_stock_functions_ws.py).

모든 체결에는 `stock_code`, `venue=KRX|NXT`, `market_phase`, `trade_at`, `received_at`, `price`, `volume`, 원본 식별자를 붙인다. 같은 종목의 1분 봉도 `venue`와 `market_phase`를 포함해 별도로 만들고, 모델이 두 시장을 함께 보도록 정규화한 통합 봉을 추가로 만들 수 있다. 두 거래소의 거래량을 합산하려면 동일 체결의 중복 수신 여부를 먼저 확인한다. 최우선 호가는 시장별로 따로 유지하고, 오래된 호가는 주문 가능 가격으로 사용하지 않는다.

## 3. 매분 예측 목표

기존의 세 시간 범위는 유지한다. 다만 “일별 종가”에는 두 개의 서로 다른 목표를 둔다.

| 출력 | 정답 정의 | 예측 당시 사용 조건 |
| --- | --- | --- |
| `p_1m` | 1분 뒤 거래 가능한 시장의 통합 기준 가격 | 현재 시세가 신선하고 계획된 목표 시각이 연속매매 구간임 |
| `p_60m` | 60분 뒤 거래 가능한 시장의 통합 기준 가격 | 현재 시세가 신선하고 계획된 목표 시각이 연속매매 구간임 |
| `p_krx_close` | 당일 KRX 공식 종가 | 15:30 확정 전 |
| `p_nxt_end` | 당일 NXT 애프터마켓 종료 전 마지막 유효 체결가 | 종목이 NXT 대상이고 현재 거래 상태가 정상이며 종료 전임 |

`p_nxt_end`는 KRX 공식 종가와 구별하기 위해 “NXT 종료 기준 가격”이라고 부른다. KRX 공식 종가를 20:00 NXT 가격으로 덮어쓰지 않는다. 예측 당시 사용 여부는 **현재까지 알려진 시세와 거래 일정**으로만 정한다. 실제 미래 목표 시각에 체결이 없거나 NXT의 마지막 체결이 너무 이른 경우에는, 결과를 확인한 뒤 해당 **학습 정답만** 무효로 표시한다. 장중 판단을 과거로 거슬러 바꾸지 않는다. 1분·60분 목표가 계획된 휴장 구간이나 동시호가 구간에 걸리면 예측 사용을 보류한다. 60분 뒤 다른 연속매매 단계에서 거래가 재개되는 경우에는 해당 단계의 가격을 목표로 삼되, 현재·목표 장 단계를 모델 입력에 포함하고 단계별 성능을 따로 평가한다. 모델은 네 출력을 가진 작은 공유 상태 모델 또는 가벼운 단계별 기준선으로 시작한다.

매분 `forecast_id`, 기준 가격·봉 ID, 각 목표 가격·목표 시각·유효 여부, 장 단계, 모델 버전과 불확실성 범위를 저장한다. NXT 프리마켓과 KRX·NXT 메인마켓에서는 `p_60m`과 `p_krx_close`를 주된 방향 근거로 쓴다. 15:30 이후 `p_krx_close`는 예측값이 아니라 확정된 관측값이며, NXT 애프터마켓에서는 유효한 `p_60m`과 `p_nxt_end`로 방향 근거가 바뀐다. NXT 프리마켓·메인마켓·애프터마켓의 가격 형성과 유동성이 다를 수 있으므로 오차 범위와 진입 기준을 단계별로 검증한다.

## 4. 매매 판단과 주문 시장 선택

판정기는 현재 장 단계에서 유효한 `p_60m`과 해당 단계의 일말 목표(`p_krx_close` 또는 `p_nxt_end`)를 주요 방향 근거로 쓴다. `p_1m`은 진입 직후 위험과 시점 조절에 사용한다. 한 출력이 무효이거나 두 주요 예측이 충돌하면 기본값은 `HOLD`다. 별도 위험 청산 규칙은 예측의 유효 여부와 독립적으로 평가한다. 새 사건 신호는 Jev가 비동기로 분류한다.

매수·매도 후보가 생기면 주문 어댑터는 **현재 실제로 열려 있고 해당 종목을 취급하는 시장**의 호가, 수량, 수수료, 예상 체결 가능성을 비교한다. 동시에 열려 있으면 한투의 `SOR` 경로를 우선 검토하고, 명시적 시장 지정 주문을 사용할 때는 현재 호가와 계좌 권한을 다시 확인한다. `KRX`, `NXT`, `SOR` 중 해당 환경에서 실제 가능한 경로를 기록한다. 주문 전에는 계좌·미체결 주문·한도·시장 상태와 호가 시각을 다시 확인한다. 초기 단계는 후보를 기록하고, 주문 연결 단계에서는 dev 모의계좌와 prd 실전계좌를 [환경별 계약](ENVIRONMENTS.md)에 따라 처리한다. [NXT 시장 개요와 최선집행](https://www.nextrade.co.kr/marketOverview/content.do), [KIS 주문 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/order_cash/order_cash.py).

## 5. 저장·복구

로컬 파일의 봉 키는 `(stock_code, venue, market_phase, minute_at)`이며, 통합 봉은 별도의 `venue=COMBINED`로 저장한다. 예측 기록과 판정 기록에는 사용한 봉의 시장·단계와 목표 정의를 넣는다. 환경별 DynamoDB의 사건·판정 인덱스에도 시장·단계·주문 경로를 작은 속성으로 보관한다. 웹소켓 누락은 시장별로 표시하고 해당 시장의 분봉을 복구한다. 한 시장만 끊긴 경우에도 통합 가격과 최선 호가를 완전하다고 가정하지 않는다.
