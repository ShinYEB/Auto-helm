# 복구·관측 상세 설계 (LLD)

> 범위: 2026-10-27~30 dev 모의투자 수집 시험. 주문 서비스는 실행하지 않는다. 범용 거래일 달력은 후속 작업이다.

## 1. 복구의 주체

Mac 로그인 세션의 `launchd`는 수집 시간 감독 프로세스와 컨트롤타워 감독 프로세스를 `KeepAlive`로 유지한다. 별도 1분 점검 작업은 Redis와 Prometheus·Grafana의 HTTP 응답을 확인한다. 수집 시간 감독 프로세스는 07:30~20:30 KST에 사건·시세·예측 프로세스를 시작하고, 5초마다 상태를 확인한다. 외부 제공처의 오류는 각 수집기의 재시도·대기 정책이 먼저 처리한다.

| 신호 | 판정 | 조치 |
| --- | --- | --- |
| 자식 프로세스 종료 | PID 종료 코드 확인 | 10초 이상 간격으로 재시작 |
| 시세·사건 하트비트 누락 | 기동 45초 유예 뒤 시세 25초, 사건 30초 초과 | 재시작 |
| 장중 시세 구독 미확정 | 해당 장 시작 또는 재기동 뒤 90초 초과 | 재시작 |
| 장중 1분봉 정지 | 마지막 봉 이후 3분 초과 | 재시작 |
| KRX 정규장 체결 중단 | 3분에 경보, 5분에 재시작 | 원본 수신 시각과 구독 상태를 함께 기록 |
| NXT 체결 중단 | 10분에 경보 | 유동성 차이를 고려해 이 신호만으로는 재시작하지 않음 |
| 예측 출력 중단 | 새 봉이 계속 생성되는데 출력이 3분 이상 뒤처짐 | 예측기만 재시작 |
| GDELT 429·뉴스 제공처 오류 | 제공처별 실패 이력 기록 | 해당 수집기의 백오프를 유지하며 전체 서비스는 재시작하지 않음 |

자동 재시작은 서비스별 **15분에 최대 3회**로 제한한다. 실행 중 건강 이상에 따른 재시작은 최소 5분, 프로세스 종료에 따른 재시작은 최소 30초 간격을 둔다. 제한에 걸리면 `RESTART_SUPPRESSED`를 기록하고 다음 허용 시각까지 기다린다. 장 구간 밖의 무수신은 장애로 판정하지 않는다. 구독 종목이 없으면 경보만 남긴다.

## 2. 기록의 역할

| 기록 | 경로 | 변경 방식 |
| --- | --- | --- |
| 현재 시세 구독·체결·봉 상태 | `data/dev/market/health.json` | 원자적 교체 |
| 현재 사건 수집 상태 | `data/dev/events/health.json` | 원자적 교체 |
| 현재 감독 상태와 미해결 경보 | `data/dev/market-day-YYYY-MM-DD.status.json` | 원자적 교체 |
| 장애 발생·해소·재시작·억제 | `data/dev/operations/incidents/YYYY-MM-DD.jsonl` | **추가 전용, 디스크 반영** |
| 사건 제공처 실패·RSS 포화 의심 | `data/dev/events/health-events/YYYY-MM-DD.jsonl` | **추가 전용, 디스크 반영** |
| 시세 원본·봉·결손, 사건 원본·분석, 예측 | 각 서비스의 날짜별 JSONL | 추가 전용 |
| Java 표준 출력·예외 | 날짜별 서비스 로그 | 추가 전용 |
| 마감 후 집계 | `data/dev/market-day-YYYY-MM-DD.report.json` | **한 번만 발행** |

상태 파일은 화면을 위한 현재값이므로 바뀌어도 된다. 오류를 조사할 때는 추가 전용 기록의 사건 ID·시각·서비스·코드를 기준으로 전후 원본과 로그를 대조한다. 재시작하면 이전 오류가 상태 파일에서 사라질 수 있지만 사건 기록은 남는다. 비밀 키, 요청 URL, 응답 원문은 운영 사건에 쓰지 않는다. 원본 데이터는 해당 서비스의 제한된 로컬 기록 경로에만 둔다.

## 3. 일일 피드백

20:30 종료 뒤 보고서는 KRX·NXT 프레임 수, `READY`·`INCOMPLETE`·`EMPTY_UNVERIFIED` 봉, 결손 원인, WebSocket·파싱 오류, 재시작, 사건 제공처 실패, Jev 분석 상태, 예측 상태를 집계한다. Grafana는 추가 전용 사건 기록을 읽은 Prometheus 지표로 장애·복구 누적과 미해결 경보를 보여준다.

장 마감 후에는 보고서에서 이상이 있었던 시각을 찾고, 같은 시각의 사건 JSONL·원본·Java 로그를 비교한다. 원인을 코드·제공처·설정·시장 무거래로 분류한 뒤 수정과 재생 테스트를 수행한다. 실패 기록 자체를 지우거나 새 실행 결과로 덮어쓰지 않는다.

## 4. 한계

프로세스 재시작은 키 오류, 제공처 장애, Mac 전원·네트워크 중단을 해결하지 못한다. KRX 무수신 규칙은 현재 관측 대상처럼 유동성이 큰 종목에 맞춘 시험값이다. 관심 종목이 바뀌면 무거래의 정상 범위를 다시 보정해야 한다. 재시작 뒤 결손 구간은 정상 봉으로 만들어 채우지 않고 별도 결손 기록으로 남긴다.
