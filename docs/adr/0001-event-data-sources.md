# ADR-0001: 공시와 일반 뉴스의 수집원 선택

- 상태: **채택 — OpenDART 공시 우선, GDELT 메타데이터 실험, 기사 본문 분석 보류**
- 결정일: 2026-10-26
- 범위: 개인용 Auto-helm의 사건 데이터 수집. 한투 시세 WebSocket은 별도 경로다.
- 근거 조사: [뉴스·공시 데이터 수집 경로 확인](../research/01-event-data-sources.md)

## 결정해야 하는 것

관심 종목의 공시와 일반 뉴스를 장중에 발견하고, 사건 분석과 매매 판단에 사용할 수 있는 데이터를 확보해야 한다. 수집원이 기사 제목·링크만 제공하는지, 원문을 제공하는지, **저장과 외부 LLM 입력을 허용하는지**에 따라 구현 가능 범위가 달라진다. 현재는 개인 프로젝트이며 유료 계약 없이 사용할 수 있는 키가 확인되지 않았다.

## 비교 기준

1. 개인이 합법적으로 신청·사용할 수 있는가.
2. 종목 관련 사건을 충분히 빠르고 안정적으로 찾을 수 있는가.
3. 원본을 저장하고 AI에 입력할 수 있는가.
4. 실제 비용과 호출 한도를 감당할 수 있는가.
5. 중복 제거용 ID, 발행·발견 시각, 정정 처리에 필요한 필드를 얻을 수 있는가.

## 사용량·가격 비교

아래 예상량은 **관심 종목 1개, 하루 13시간 수집, 월 20거래일**이라는 비교용 가정이다. 뉴스 검색어 하나를 3분마다 조회하면 `13 × 20 × 20 = 5,200회/월·검색어`다. 검색어가 늘면 요청량도 비례해 증가한다. 공시를 15분마다 전체 목록 1페이지씩 조회하면 `13 × 4 × 20 = 1,040회/월`이며, 페이지가 늘면 실제 호출 수도 늘어난다. 요금이 검색어·매체·기간·상품별로 다르면 이 요청 수만으로 가격을 확정할 수 없다.

## 실제 시험과 한계

2026-10-26 13시대 KST에 로컬 Mac에서 GDELT DOC API를 `mode=artlist`, `format=json`, `sort=datedesc`, `maxrecords=100`으로 호출했다. 기사 내용은 저장하지 않았고 결과 개수·HTTP 상태·응답 시간만 기록했다. **최초 연속 요청은 2초 간격으로 실행했으며, 이후 429 응답 본문에서 최소 5초 간격 요구를 확인했다.** 이 시험 설정은 제공처 제한을 지키지 않았으므로 429를 서비스 불안정성이나 일반적인 허용량의 증거로 해석하지 않는다.

| 질의 | 범위 | 관찰 결과 |
| --- | --- | --- |
| `삼성전자` | 최근 1시간 | HTTP 200, 약 17.2초, 기사 0건 (`{}` 반환) |
| `SK하이닉스` | 최근 1시간 | HTTP 429, 약 10.9초 |
| `Samsung Electronics` | 최근 1시간 | HTTP 429, 약 11.3초 |
| `"Samsung Electronics"` | 최근 24시간, 별도 재시도 | HTTP 429, 약 12.0초 |

이는 **한 시점의 작은 연결 시험**이다. GDELT가 해당 기업 뉴스를 항상 누락한다는 뜻은 아니다. 429 본문은 “5초마다 최대 한 요청”을 요구했고 `Retry-After` 헤더는 없었다. 나중에 5초 이상 간격을 두고 한 번 더 요청했을 때도 429였으므로 추가 제한 창이나 공유 IP 사용량이 있을 수 있지만, 정확한 원인은 응답으로 확인되지 않았다. [GDELT의 호출 제한 설명](https://blog.gdeltproject.org/ukraine-api-rate-limiting-web-ngrams-3-0/)

초기 출처 비교 당시에는 OpenDART와 뉴스토어 테스트베드의 키가 없어 **인증된 응답·실제 지연·일일 호출량을 시험하지 못했다.** 이후 OpenDART 키로 2026-10-26에 공시 목록과 원본 ZIP 수집을 확인했다. 뉴스토어의 계약·권한 및 실제 호출은 아직 확인하지 않았다. 네이버는 현행 이용 조건상 이 용도의 API 호출 시험을 진행하지 않았다.

같은 날짜의 `event-data` 기록에는 OpenDART 사건 1건과 해당 공시 ZIP 1개가 남았다. GDELT 메타데이터 조회에서는 제한 응답과 오류가 관측됐고, 사건으로 기록된 뉴스 후보는 없었다. 이는 초기 연결 시험의 후속 관찰이며, 뉴스 포괄성이나 지속적인 수집 성공률을 입증하지 않는다.

## 결정

1. **공시:** OpenDART를 첫 사건 수집원으로 채택한다. `corpCode.xml`로 종목을 매핑하고, `list.json`을 장중 15분 배치·겹침 조회로 읽는다. `last_reprt_at=N`으로 정정 보고서를 포함하고, 새 `rcept_no`만 원본 `document.xml`을 받는다. 목록의 `rcept_dt`는 날짜뿐이므로 정확한 공개 시각으로 취급하지 않고 최초 발견 시각을 별도로 남긴다.
2. **일반 뉴스 메타데이터 실험:** GDELT가 공개한 기사 제목·URL·출처·시각만 탐색 후보로 선택한다. [GDELT의 데이터 이용 조건](https://gdeltproject.org/about.html)에 따라 출처를 명시한다. 동일 정규화 URL은 **성공한 AI 분석을 한 번만** 수행하고 결과를 저장해 재사용한다. 링크를 따라가 언론사 기사 본문을 자동 수집·입력하지 않는다. 메타데이터만으로 종목 영향이나 매매 신호를 확정하지 않는다. GDELT의 실제 응답과 국내 종목 발견 지연이 검증되기 전에는 판단기 입력을 활성화하지 않는다.
3. **요청 간격:** GDELT DOC 질의는 전체 종목·검색어를 통틀어 **최소 10초 간격**, 같은 질의의 조회는 **3분 주기**로 시작한다. 검색어가 많아 3분 안에 모두 처리할 수 없으면 요청을 겹쳐 보내지 않고 다음 실행으로 넘긴다. GDELT 2.0 기반 데이터는 [15분 주기로 갱신](https://gdeltproject.org/data.html)되므로 연속 조회에서 새 결과가 없을 수 있다. 최근 30~60분을 겹쳐 조회하고 URL로 중복 제거한다. 429가 오면 `Retry-After`가 있으면 그 값을 따르고, 없으면 1분→2분→4분→최대 15분으로 대기 시간을 늘리며 반복 요청을 멈춘다. 10초 간격도 성공을 보장하지 않으므로 관찰 결과로 조정한다.
4. **기사 본문 후보 검증:** 뉴스토어 AI용 상품 또는 동등한 라이선스의 제공처에 대해 개인 계약, 외부 모델 입력, 실시간 지연, 가격을 확인한다. 계약·키가 확보되면 같은 종목으로 3거래일 이상 발행 시각·최초 발견 시각·누락·중복·비용을 측정한 뒤 뉴스 ADR을 갱신한다. 네이버 검색 결과와 뉴스토어 일반 상품은 **한 번의 AI 추론이라도** 약관상 금지된 AI 활용 범위로 취급한다.

## 결과와 재검토 조건

공시 수집은 뉴스 계약과 독립적으로 구현할 수 있다. GDELT 실험 중이거나 기사 본문 권한이 없는 동안에는 뉴스 신호를 `NOT_AVAILABLE`로 표시하고, 판단기가 기사 부재를 긍정 신호로 해석하지 않게 한다. PRD의 뉴스 요구사항은 아직 충족되지 않으므로 **관찰 MVP 완료로 표시하지 않는다.**

OpenDART 키가 준비되면 1~2개 종목에서 당일 목록, 정정 공시, 원본 ZIP, 페이지 증가와 15분 배치의 발견 지연을 측정한다. API 응답이 예상과 다르거나 제한에 걸리면 호출 주기와 조회 범위를 바꾸고 이 ADR을 갱신한다. 뉴스 계약·가격·권한이 확정되면 별도 ADR로 최종 뉴스 수집원을 선택한다.
